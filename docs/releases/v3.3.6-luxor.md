# v3.3.6 Luxor

Released: 2026-10-19

## Summary

3.3.6 is a one-change patch: the process that goes with the Decisions tab. 3.3.5 shipped
the tab, which turns `codev/state/pending-decisions.md` into cards and writes the owner's
word back into the file, but the agreement behind it, what an item looks like, how an
architect sends one, and what the hub architect does with each ruling, existed only in one
adopter's repository. This release puts that document in the framework, points the architect
role at it, and pins its format to the code with a test.

## The owner decisions process (#1826, PR #1832)

`resources/decision-protocol.md` now ships in the Codev skeleton. It describes the loop end
to end:

- **One file, one hub.** Every ask for the owner's word is one item in
  `codev/state/pending-decisions.md`; one architect named `main` is the hub and the only
  agent that edits the file. Other architects send items with
  `afx send architect:main 'DECISION <name>-<n>: <question> …'`.
- **The item.** A `###` heading of id, time stamp with its zone, and the question; a short
  body of labelled lines (Problem, Options, Fix, Testing, Recommendation, Links); and one
  `**Your word:**` line whose backticked, `/`-separated words become the card's buttons, the
  first one marked as recommended.
- **What the tab reads.** The exact parsing rules: which headings are items, which zones the
  stamp converts from, how a bare word takes its description from the `**Options:**` line,
  and how a question-and-answer thread shows on the card.
- **What the hub does.** Post, learn of rulings (from the tab, the file or chat), answer
  questions, relay `RULING <id>: <word>` to the asking architect with the owner's comment
  carried verbatim, record the ruling and its `DONE` line under `## Ruled`, and scan the file
  on every resume.

The architect role gained a three-line pointer to the document, and the Tower command
reference links it from its Decisions tab section. A new test runs the document's own
fenced examples through the Decisions tab's parser, splicer, notice builder and stamp
resolver, so the document cannot drift from the code without failing CI.

The document resolves from the installed package: `codev init`, `adopt` and `update` do not
yet copy skeleton reference documents into an adopter's `codev/resources/`. Until #1834
lands, read it in the package under `skeleton/resources/decision-protocol.md`, or on GitHub
at `codev-skeleton/resources/decision-protocol.md`.

## Upgrade

```bash
npm install -g @cluesmith/codev@3.3.6
codev update
```

Nothing changes for a workspace without a decisions file: the tab appears only when the
file exists, and the hub notice goes only to an architect named `main`.
